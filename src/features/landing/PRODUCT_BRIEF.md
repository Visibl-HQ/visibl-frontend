# Visibl Landing Product Brief

## Product Truth

Visibl is an evidence-structured founder workspace. It turns raw founder context into a company map, challengeable field cards, memory pins, gated artifacts, versioned idea history, hosted pitch pages, analytics, and iteration loops.

The landing page must not frame Visibl as a deck generator, AI advisor, generic chatbot, or Notion clone. The credible frame is: messy startup thinking becomes structured company logic that can be tested, shared, revised, and trusted.

## Core Workflow

1. Founder enters unstructured startup context in a deep conversation.
2. Visibl extracts memory pins and company map fields.
3. Weak fields are marked missing, vague, assumed, supported, contradicted, or not applicable.
4. Investor and customer artifacts stay gated until the required context is usable.
5. Significant changes become commits in the idea history graph.
6. The founder publishes controlled public, gated, or private sections.
7. Page views, feedback, objections, and validation events return to the workspace.

## User Pain

Early founders do not only need better words. They need a place where fragmented notes, chat history, claims, objections, and pivots become a coherent operating model. The emotional problem is private chaos before public explanation.

## Differentiators To Show Visually

- Live company map instead of static prompts.
- Memory pins as visible shared context.
- Structure gates that prevent unsupported output.
- Idea history as a graph of reasoning, not a changelog gimmick.
- Hosted pages with visibility controls and feedback loops.
- GTM playbooks that resolve to executable founder actions.

## Emotional Positioning

Visibl should feel like a calm observatory for building a company: atmospheric, precise, reflective, and quietly intense. The founder is not being sold productivity. They are being invited to make the company visible enough to survive scrutiny.

## Visual Language

- Editorial serif headlines paired with restrained sans UI.
- Dusk, graphite, ink, cyan, rose, and soft gold accents.
- Large whitespace, slow pacing, and cinematic framing.
- Product UI should appear as a luminous instrument panel, not a dashboard template.
- Motion should feel physical and slow: drift, reveal, parallax, focus, and glow.

## Research Notes

- Lenis is used for smooth scroll because its current package supports performant smooth scrolling and a React package surface.
- Motion scroll-linked effects should stay on transform, opacity, clip-path, or filter paths where possible.
- Reduced motion must have a first-class path: parallax and decorative looping movement are disabled or softened.
- Magic UI search surfaced animated grid, particles, border beam, shine border, aurora text, and reveal primitives. These are inspiration only; the implementation is custom and unified.
